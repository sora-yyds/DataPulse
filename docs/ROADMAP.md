# DataPulse AI 实施路线图

## 1. 文档目的与执行规则

本路线图把已确认的产品与架构决策转化为可执行、可验收的 MVP 实施顺序。阶段按依赖关系而不是日历日期或团队人数划分；只有满足退出标准，阶段才算完成。若阶段门槛未通过，应执行该阶段写明的回退，而不是把缺陷顺延到 M4。

路线图的权威边界来自领域词汇表、[ADR-0043](adr/0043-vertical-slice-mvp-milestones.md)、[ADR-0044](adr/0044-freeze-mvp-boundaries.md) 及其引用的最新 ADR。已经被取代的 ADR 不作为实现依据。

共同执行原则：

- 每个阶段交付一个可运行的纵向切片，不以孤立组件“开发完成”替代端到端验收。
- 原始数据只在浏览器本地处理；设备不足或输入超限时明确拒绝，不抽样、不截断、不转云端。
- 故事蓝图 JSON Schema 是创作端、观看端、项目包和发布包的唯一结构规范，所有正式版本保留永久迁移链。
- 确定性分析负责全部数值；模型只消费证据包并组织故事。无模型凭据时，核心闭环仍必须可用。
- 自动化质量门槛必须能在公开仓库的 Fork 中完整复现；真实供应商与真实设备认证作为官方实例额外发布门槛。
- “十分钟可分享成果率”是待真实用户研究验证的假设，不得用自动化通过率替代或对外宣称已经达成。

## 2. 阶段总览

| 阶段 | 纵向切片 | 核心结果 |
|---|---|---|
| M0 工程底座 | 仓库、Schema、存储、分析探针、CI、部署骨架 | 证明技术边界可行，并形成后续可共同演进的契约 |
| M1 本地闭环 Alpha | 导入 → 本地分析 → 基础生成 → 编辑联动 → 版本 | 无密钥、无云端即可完成可编辑故事闭环 |
| M2 AI 增强 Beta | 证据包 → 模型配置与调用 → 结构化增强 → 可撤销应用 | 三类模型适配路径可验证，AI 不越过数值与数据边界 |
| M3 分享闭环 Beta | 完整渲染 → 加密发布 → 观看交互 → PDF/PNG | 形成可临时分享、可撤销、可本地导出的完整成果 |
| M4 公开 MVP | 全量语料、兼容性、安全、外部认证、自部署与发布 | 所有强制门槛通过并发布可复现的公开版本 |

## 3. M0：工程与正确性底座

### 3.1 目标

建立单一公开 monorepo、版本化故事契约、可复现 CI、本地加密存储和官方／社区部署骨架；用真实参考设备验证浏览器本地分析与公开输入上限是否可兑现。M0 的重点是尽早关闭不可逆的 Schema、存储、性能和数据驻留风险。

### 3.2 依赖

- 已冻结的 MVP 范围与统一领域语言。
- 参考创作设备：4 核 CPU、8 GB 内存、集成显卡、最新稳定版 Chrome 或 Edge。
- 加密 profile 冻结所需的最小真实设备探针：至少一台当前 iOS Safari、一台 Android 微信和一台 iOS 微信；只验证 KDF/AES/JCS/Fragment 固定向量与资源可行性，不替代 M4 完整设备认证。
- 可用于持续测试的合成小型、常见档、行上限窄表和较短宽表夹具。

### 3.3 工作包／Epic

**M0-E1：公开 monorepo 与治理骨架**

- 建立 pnpm workspaces 与 Turborepo；创作端和观看端使用 TypeScript 严格模式、React、Vite 独立构建，服务使用 TypeScript、Hono 与 Node.js LTS。
- 划分共享故事 Schema、领域模型、本地分析、纯 `metric-runtime`、渲染、加密和供应商适配边界；创作端、观看端与低权限自定义连接器独立构建，避免复制契约或让连接器依赖创作端存储。
- 落地 AGPL-3.0、受保护 `main`、短分支／Fork PR、merge queue、squash merge、Conventional Commit PR 标题、Changeset 和敏感路径 `CODEOWNERS` 骨架。

**M0-E2：故事 Schema 与迁移框架**

- 发布初始版本化 JSON Schema，覆盖 `schemaVersion`、故事区块、数据绑定、分析条件、证据引用、叙事规则、布局与视觉选择。
- 建立“在副本上逐版本迁移 → Schema 校验 → 成功后替换”的迁移执行器、历史样本目录和失败保留原项目机制。
- 让创作端、观看端、项目包和发布包从同一 Schema 生成类型并执行 Ajv 边界校验。

**M0-E3：本地存储与加密骨架**

- 用 IndexedDB 保存元数据、版本索引、能力测试和不可导出设备密钥；用 OPFS 保存加密数据集、Arrow 数据和大型资源。
- 建立设备绑定 Web Crypto 密钥、持久存储请求、写入前配额／完整项目包大小双检查和双存储事务恢复；任何已提交项目都保持完整 payload ≤4 GiB 且可备份。项目包采用随机 256 位包密钥、`a2id-v1-64m-t3-p1` KEK、用途隔离 AES-256-GCM、4 KiB 头、1 MiB 独立认证分块和无二次压缩的版本化流式信封。
- 在 Chrome／Edge 与最小三类真实观看设备运行相同 KDF/AES/JCS/Fragment 固定向量，记录设备／系统／浏览器、派生耗时和内存终止情况；只有代表设备单次派生 ≤5 秒且固定向量一致才冻结 `a2id-v1-64m-t3-p1`。
- 原文件 Blob 只通过 File API 瞬时读取，验证它不会写入 IndexedDB、OPFS、日志或网络请求。

**M0-E4：本地分析性能探针**

- 将 ExcelJS、CSV 解析、DuckDB-WASM 和 Arrow glue 打成无运行时 import 的单文件模块 Worker；固定 WASM／扩展在交付原始数据前由主线程预取、哈希校验并结构化克隆传入。Worker CSP 禁止连接、网络脚本源与嵌套 Worker，仅保留确需的 WASM 执行能力。
- 在导入前实现文件、行、列、非空单元格、`.xlsx` 解压大小／压缩比和峰值工作内存估算器。
- 在真实参考设备和固定浏览器环境中运行小型、常见档、20 万行窄表、50 MB／100 列较短宽表；不得用“20 万行 × 100 列同时满载”作为承诺。

**M0-E5：测试与 CI 底座**

- 配置 Vitest、React Testing Library、Storybook、Playwright 和 GitHub Actions。
- 建立 PR 快速检查、merge queue 完整可复现矩阵、`main` 复核和正式发布门槛；从 M0 起保存固定随机种子、浏览器、视口、字体、语言和时区元数据。
- 为数值、Schema／迁移、视觉、无障碍、端到端和性能六类强制门槛建立声明性的 `planned` 目录项与失败阻断规则；用版本化退出 manifest 冻结 M0 gate 全集与静态定义，record 一 gate 一记录且只追加。目录项本身不运行成功空脚本、不进入日常绿色聚合，并持续使当前里程碑退出聚合失败，直到同一变更加入真实断言、根脚本与 check 名并激活；M0 退出还必须以本次 nonce 重跑全部自动 gate，不能只信历史状态。

**M0-E6：部署与安全骨架**

- 用公开基础设施即代码建立官方实例最小骨架：创作端、观看端、API、自定义连接器四个独立 Origin，连接器每个安全纪元使用不承载其他应用的独占可注册域；配套北京地域 OSS/CDN、函数计算／API 网关、发布密文 OSS Bucket、Tair 临时 KV，社区参考以相同 Origin／注册域边界 + Valkey 替代 Tair。
- 配置发布对象不超过 24 小时的 OSS 生命周期与定时清理双路径；应用服务保持无状态，不创建账号、项目或用户内容数据库。
- 从第一条请求起清除 Authorization、请求正文、证据包和发布密文的日志／错误上报；建立逐应用 CSP、模块 Worker 禁网、连接器安全纪元 Origin／独占可注册域／每请求 iframe／消息 Schema／`Clear-Site-Data`／`worker-src 'none'`、DataPulse 页面与 API 无 Cookie／基础设施 Cookie 强制 `__Host-; Secure; Path=/` 且无 `Domain`、逐路由精确 CORS 和依赖治理检查。

### 3.4 交付物

- 可公开构建的 monorepo、开发命令、测试命令和最小部署说明。
- 初始故事 Schema、迁移器、历史样本与创作／观看最小渲染页。
- IndexedDB／OPFS 加密存储原型，以及带固定 KDF／JCS／AES-GCM 互操作向量的版本化密码项目包往返原型。
- M0 最小真实 Safari／微信加密探针记录；明确标注它不是 M4 完整版本／设备认证。
- 本地分析性能报告，逐项记录参考设备、夹具、峰值内存、耗时、失败原因和公开上限结论。
- 官方北京基础设施与社区 Valkey 参考配置的四 Origin 可部署骨架。

### 3.5 强制验证

- Fork 在不依赖付费专有测试 SaaS 的情况下能完成安装、构建和当前全部测试。
- 故事 Schema 非法输入被拒绝；历史样本能迁移并渲染；迁移失败不破坏原副本。
- 清除站点数据会同时使设备密钥与项目不可恢复；新增版本／资源在使完整备份超过 4 GiB 前被阻止。项目包固定向量、首／中／尾分块、重排／截断／尾随、篡改／错误口令／未知 profile 测试通过；4 KiB header、文件／分块 framing、计数与 4 GiB payload 声明上限在 KDF 前拒绝，1 MiB manifest 上限在首块认证解密后且分配／解析前拒绝。项目包不含模型凭据或既有发布管理凭证。
- `a2id-v1-64m-t3-p1` 在 Chrome／Edge、当前 iOS Safari、Android 微信和 iOS 微信最小真实设备探针中固定向量一致、单次派生 ≤5 秒且不发生内存终止；失败时在 M1 前选择新的 profile ID 并重跑，不放宽为链接自带参数。
- 资源探针严格验证：文件 ≤ 50 MB、行 ≤ 200,000、列 ≤ 100、非空单元格 ≤ 5,000,000、`.xlsx` 解压 ≤ 500 MB、压缩比 ≤ 100:1、预计峰值工作内存 ≤ 1.5 GB。
- 参考设备上的边界档全链路可行性必须支持既有 3 分钟目标；常见档同时以 60 秒完整草稿目标建立基线。
- 四 Origin 否定测试证明观看端／连接器不能读取创作端 IndexedDB、OPFS、CryptoKey、`__Host-` Cookie 或 Service Worker；在不同可注册域的 HTTPS 测试主机上，预置于连接器 Origin 的 IndexedDB／OPFS／Cache 及连接器独占可注册域的 Cookie 在新 iframe 执行代码前被清除，创作端／观看端／API 状态与 `__Host-` Cookie 不受影响，任何基础设施 Cookie 都满足 `__Host-; Secure; Path=/` 且无 `Domain`，Service Worker 注册失败且下一请求无残留；安全演练证明轮换后 Creator 拒绝旧纪元 Origin。不同端口不得作为 Cookie 隔离证据。交付带标记原始数据后，Worker 的 fetch/WebSocket/EventSource/sendBeacon、同源动态 import、`importScripts` 和嵌套 Worker 均不产生请求；伪造连接器消息与宽松 CORS 被拒绝。
- OSS 生命周期和定时清理都能删除测试密文；Tair／Valkey 测试键具有强制 TTL，日志中没有受禁止内容。

### 3.6 退出标准

- M0-E1 至 M0-E6 的交付物均在干净环境可重现，merge queue 的全部当前门槛为绿色；冻结 M0 manifest 中每个 gate 均有状态一致的唯一最新通过记录，全部自动 gate 在退出候选本次重跑通过。
- Schema、迁移、存储和分析探针已形成一个最小端到端切片，而不是四个互不连接的演示。
- 资源边界有明确的“通过”证据；若任一公开上限或 3 分钟目标无法兑现，已在进入 M1 前下调公开上限并同步夹具与文档，未采用云端回退。
- 官方和社区部署骨架均证明“四 Origin 强制隔离、无长期用户内容数据库、仅 TTL 运行状态”可以成立。

### 3.7 风险与回退

| 风险 | 回退 |
|---|---|
| DuckDB-WASM／ExcelJS 峰值内存超过参考设备预算 | 在 M1 前下调可公开承诺的输入上限；保留明确拒绝，不抽样、不转云端 |
| IndexedDB 与 OPFS 事务不同步 | 保留加密临时写入和提交标记；恢复到最后一个完整索引，不自动删除用户版本 |
| Schema 过早固化阻碍迭代 | 仍通过显式版本和迁移演进，不允许绕过 Schema 或让两端持有不同结构 |
| 云资源生命周期配置失效 | 阻止后续分享功能上线；由定时清理作为第二路径，但不能把它当作延长留存的许可 |

## 4. M1：本地闭环 Alpha

### 4.1 目标

在无账号、无模型密钥、无云端分析的条件下，完成“导入单个规范表 → 质量检查 → 本地分析 → 基础生成 → 编辑时间范围并联动重算 → 保存故事版本”的完整闭环。

### 4.2 依赖

- M0 的 Schema、迁移、本地加密存储、分析运行时和已确认资源上限。
- 至少一个能表达标题／摘要、KPI、时间趋势或分类比较的受控主题与核心区块子集。

### 4.3 工作包／Epic

**M1-E1：受控导入与字段语义**

- 支持单个 `.xlsx` 或 CSV 形成单一规范表；Excel 只读取工作表、显示格式和缓存公式结果，不执行公式、宏或任意代码。
- CSV 编码按已确认范围处理 UTF-8、GBK、GB18030；不支持格式必须明确拒绝。
- 识别并允许纠正时间、分类维度、数值度量、唯一标识、自由文本和直接标识六类字段角色；机密性由所有者附加标记。
- 显示导入范围、故事时区和数据截止点；无时区值以 `Asia/Shanghai` 形成可见、可修改的分析假设。

**M1-E2：确定性质量与分析语义**

- 原始数据集版本不可变；缺失值默认排除但显示缺失率，重复记录只提示，只有所有者指定判重字段后才形成可撤销处理，异常值只标记。
- 默认保留 Top 8 并把长尾显式聚合为“其他”；未完整周期只做同进度比较；多币种分开分析，不自动换汇；显示尺度不改变底层单位。
- 零基期不用百分比；有效样本少于 30 时标记小样本并禁止强结论；比较基准只来自上期、去年同期、数据内对照组或所有者提供目标。
- 不生成预测或因果结论；所有数值陈述绑定指标／证据 ID，评价性语言绑定阈值或判定规则。

**M1-E3：指标与叙事引擎**

- 实现基础指标 `SUM`、`AVG`、`MIN`、`MAX`、`COUNT_ROWS`、`COUNT_VALID`、`COUNT_DISTINCT` 及受控指标条件。
- 实现创作／观看共享的纯 `metric-runtime` 与版本化 `MetricAccumulator`：`AVG` 合并 `sum + count`，`COUNT_DISTINCT` 合并精确集合，派生指标在基础累加器完成后求值；禁止相加分组去重数或改用近似值。
- 用可视化表达式树组合指标、数值常量、括号和 `+ - × ÷`；校验单位／币种，除零返回带原因的“不可用”，并提供环比、同比、目标差异。
- 生成可复算证据、判定状态和叙事规则；观看范围变化时不依赖模型即可更新、隐藏或标记失效结论。

**M1-E4：基础生成与受控编辑器**

- 确定性地生成通常由 4–8 个区块组成的响应式滚动故事；证据不足时生成受限草稿并说明限制，不填充无依据内容。
- 首个主题和核心区块必须证明标题／摘要、KPI、时间或分类图表能够共享指标语义和分析条件。
- 以直接控件完成标题、汇报目标、时间范围、区块顺序、全宽／分栏／重点布局、兼容图表切换和受控指标编辑；所有操作可见、可撤销、可重做并自动保存。
- 分析条件变化后，界面 100 ms 内响应；KPI／图表在常见档 1 秒、最大档 2 秒内更新；洞察在 5 秒内本地完成有效性处理。

**M1-E5：版本与本地迁移闭环**

- 每次成功导入创建不可变数据集版本；数据更新时要求字段映射确认并复用汇报目标、指标、布局和视觉设置。
- 草稿绑定当前数据集版本；只在首次生成成功、主动保存、更换数据前有未固化修改、新数据生成完成和发布前创建故事版本。
- 按 `project-envelope-v1` 完成项目包流式导出／OPFS 暂存导入、迁移、协议固定向量与失败恢复；新增版本前保持完整可备份 payload ≤4 GiB，禁止整包内存缓冲，只有全部分块 tag、manifest 与 entry 哈希通过后提交。导入后要求重新配置模型，既有发布管理凭证不迁移。

### 4.4 交付物

- 可安装运行的创作端 Alpha 和无模型凭据的基础生成流程。
- 数据质量报告、字段角色／假设编辑器、指标构建器、故事编辑器和版本历史界面。
- 核心区块 Storybook 状态、分析算法黄金断言和本地闭环 Playwright 用例。
- 资源拒绝、受限草稿、项目包恢复和数据更新的用户可见错误／确认流程。

### 4.5 强制验证

- 支持范围内的有效表格完成导入、规范化、基础生成、时间范围修改、指标／图表／结论联动与版本保存，全程没有原始文件网络请求。
- 超限、格式错误、压缩炸弹或内存估算超限输入被明确拒绝，不崩溃、挂起、静默抽样或转云端。
- 常见档完整草稿目标 ≤ 60 秒，其他获准边界档目标 ≤ 3 分钟；任何生成任务超过 5 分钟必须明确失败并允许重试。
- 所有数字、百分比和评价性文案都能追溯到证据引用、分析条件与判定规则；错误币种相加、除零、零基期百分比、小样本强结论和分组 `COUNT_DISTINCT` 相加均被阻止。
- 普通编辑不产生版本洪水；规定的五类检查点都产生不可变故事版本，历史版本可复现。

### 4.6 退出标准

- 一次本地浏览器会话可以无协助完成 M1 全闭环，刷新后草稿、数据集版本和撤销所需状态可恢复。
- 核心闭环在 M0 的固定基准矩阵上满足正确性、绝对时延和相对性能要求；相对 `main` 多次运行中位数退化超过 15% 会阻止合并。
- Schema、迁移、数值、编辑交互和核心端到端测试全部进入 merge queue 强制门槛。
- 没有任何必须依赖 AI、账号或云端原始数据分析才能完成的 M1 操作。

### 4.7 风险与回退

| 风险 | 回退 |
|---|---|
| 数据字段不足或质量差，无法形成完整故事 | 生成受限草稿并列明限制；不凑区块、不编造基准 |
| CSV 编码或 Excel 缓存公式结果不可可靠读取 | 明确要求用户提供支持格式或有效缓存值；不执行公式、不引入宏支持 |
| 时间范围联动超出时延预算 | 减少非必要同步渲染并保留确定性结果；不得用模型异步结果遮盖数值延迟 |
| 新数据字段不兼容旧蓝图 | 停在字段映射确认，保留旧数据集和故事版本；不覆盖历史版本 |

## 5. M2：AI 增强 Beta

### 5.1 目标

在 M1 确定性闭环之上加入可预览的证据包、百炼／Glosc／自定义端点三类 BYOK 连接和结构化 AI 增强；模型只能改善汇报目标、组织、文案与受控视觉选择，不能重算或改写事实。

### 5.2 依赖

- M1 的指标、证据引用、叙事规则、故事 Schema、撤销系统和基础生成降级路径。
- [模型供应商 API 兼容性核验](research/model-provider-api-compatibility.md) 中的已确认事实与待实测项。

### 5.3 工作包／Epic

**M2-E1：证据包与外发预览**

- 只纳入列结构、字段角色、获准统计、已计算指标／洞察／证据，以及每个获准分类字段最多 20 个且至少出现 5 次的高频标签。
- 唯一标识、直接标识、机密字段、自由文本和稀有分类值在所有配置与请求路径中绝对排除，不提供覆盖、调试或供应商例外；调用前展示完整外发预览，所有者只能进一步排除字段。
- 将模型返回的数字位置限制为有效证据引用，由本地渲染器填值；硬编码额外数字、未知 ID 或口径不匹配均使蓝图校验失败。

**M2-E2：BYOK 与本地模型配置**

- 模型凭据默认只保存在当前会话；用户明确选择“记住”后才使用设备绑定加密持久化。
- 模型配置保存前，用不含真实数据的合成请求验证鉴权、模型、简体中文和故事蓝图 JSON；展示当前实际服务条款／隐私政策链接，逐项标明留存、训练、上游／分包商、地域、删除的已核实事实与“供应商未公开／待确认”项。
- 首次发送真实证据包前确认当前披露版本；条款版本／链接、自定义 Base URL 或其条款链接变化后重新确认，确认记录仅本地保存。
- 模型只能从模型目录选择，不提供手填模型 ID：百炼使用 DataPulse 维护的北京地域版本化目录；Glosc 使用鉴权后的 `/models`；自定义端点必须提供鉴权后的 OpenAI-compatible `GET /models`。

**M2-E3：三类连接适配器**

- 百炼（北京）经无状态代理，后端只接受经校验的 Workspace ID 并从固定北京专属域名模板构造地址；不允许把代理变成任意 URL 转发器。
- Glosc AI 经无状态代理，按所选模型探测 `json_object` 与流式能力；公开文档未确认的能力不得默认开启。
- 自定义 Base URL 只由独立低权限、版本化安全纪元连接器 Origin 直连；每个纪元使用不承载其他应用的独占可注册域。每次请求新建 `allow-scripts allow-same-origin` 跨 Origin 沙箱 iframe，响应先用 `Clear-Site-Data` 清空连接器 Origin 的 cache/storage 与其独占可注册域的 Cookie，并从该纪元首次响应起以 `worker-src 'none'` 禁止 Service Worker；创作端以精确 `targetOrigin`／`event.source`、一次性 nonce 和版本化 Schema 通过 `postMessage` 传递当前请求材料。公网必须 HTTPS、支持 CORS、禁止重定向，localhost 可用，并兼容 Chat Completions 和 `/models`；列表不可用、为空或不兼容时拒绝配置。
- 当前连接器纪元疑似污染时必须轮换到从未使用的新 Origin，Creator 拒绝旧纪元，并要求自定义端点重新完成 CORS／连接测试；不得声称用同 Origin 的清理响应可以绕过既有恶意 Service Worker。
- 连接器不得读取创作端存储／CryptoKey，以 `credentials: omit` 请求，不调用 DataPulse 代理；完成、取消或超时后销毁 iframe，下一请求不得读到任何历史材料。
- 能力测试与结果只保存在浏览器本地；切换端点或模型后重新验证。

**M2-E4：结构化增强与自然语言编辑**

- 每次 AI 增强默认一次调用；只有结构校验失败时允许一次修复调用，第二次失败后明确停止。
- 网络、限流、余额或供应商错误不自动重试，由用户确认后重试；流式输出必须缓冲完整 JSON 后再校验和应用。
- AI 变更以受控蓝图补丁预览并可撤销；自然语言编辑也只能转换为同一受控操作，不执行任意 JavaScript、CSS、WebGL、SQL 或公式文本。
- 无密钥、额度不足、供应商故障或增强失败时，保留 M1 基础故事和用户已有编辑。

### 5.4 交付物

- 证据包生成器、调用前预览／排除界面和外发内容断言。
- 百炼北京、Glosc AI、自定义端点配置界面、模型目录、条款披露版本状态和合成连接测试。
- 无状态供应商代理、独立低权限连接器、严格消息协议、日志脱敏和浏览器直连安全校验。
- AI 增强／一次修复／用户确认重试／确定性回退的端到端用例。
- 录制响应和模拟供应商契约夹具；真实供应商验证脚本与公开检查清单。

### 5.5 强制验证

- 录制响应与模拟供应商覆盖成功、无效 JSON、未知证据 ID、输出截断、401、404、429、500／503、超时、取消和第二次结构失败。
- 任何模型请求都不含原始行、文件名、唯一标识、直接标识、机密字段、自由文本、稀有值或被用户排除的字段；不存在可启用这些内容的 UI、配置或调试旁路。
- 代理不记录密钥或请求正文，不接受任意主机；自定义端点不会经过 DataPulse 代理，重定向、伪造来源／nonce、重放和 Schema 外消息被拒绝；连接器预置存储在脚本执行前清除，Service Worker 注册失败、跨请求无残留，安全纪元轮换后旧 Origin 被拒绝。
- 三类连接均只能从已发现／维护目录选择模型；不能发现模型时不可保存配置。
- 首次真实证据包调用在未确认当前条款披露时被阻止；披露版本或链接变化使本地确认失效，确认状态不会上传。
- AI 增强前后所有指标数值保持由同一确定性计划产生；增强补丁失败不会损坏草稿。

### 5.6 退出标准

- 同一项目可在“无密钥基础生成”和“三类 BYOK 连接中的任一已验证配置”之间切换，基础闭环始终可用。
- 证据包预览、模型目录、连接测试、条款链接／未知项／本地确认版本、一次修复和错误重试都具有可测试的显式状态。
- 模拟／录制契约测试成为可复现 CI 门槛；真实密钥脚本、条款检查表和中国大陆网络检查表已经准备好，留待 M4 官方发布认证执行。
- 没有手填模型 ID、自定义端点代理、平台代理额度或模型计算指标的旁路。

### 5.7 风险与回退

| 风险 | 回退 |
|---|---|
| 供应商模型或协议漂移 | 将能力标记为未验证并要求重新测试；基础生成继续可用 |
| Glosc 某模型不支持 JSON Mode 或稳定流式 | 回退非流式和强约束提示／JSON 提取／本地 Schema 校验；仍只允许一次结构修复 |
| 自定义端点 CORS、连接器隔离或 `/models` 不兼容 | 明确判定 MVP 不可用；不开放手填 ID、不让创作端放宽 `connect-src`，也不通过后端代转 |
| 第三方留存、训练或地域条款不清晰 | 展示实际链接并把对应项标记“供应商未公开／待确认”，仍要求用户在首次真实外发前确认该不确定性；不扩展 DataPulse 的 24 小时承诺，不宣传 SLA 或境内驻留 |

## 6. M3：分享闭环 Beta

### 6.1 目标

完成首批故事区块、四个主题、轻量品牌、渐进式 3D、端到端加密临时分享、观看端确定性交互及浏览器本地 PDF／PNG 导出，形成真正可分发的成果。

### 6.2 依赖

- M2 已稳定的故事 Schema、指标／证据／叙事规则、编辑器和版本检查点。
- M0 的临时云架构、加密与 TTL 状态骨架。

### 6.3 工作包／Epic

**M3-E1：完整受控渲染系统**

- 实现首批区块：标题／摘要、KPI、折线／面积、柱状／堆叠、环形、散点／气泡、热力、直方／箱线、矩形树图和明细表。
- 图表切换必须通过字段角色、数据类型、样本量和分类数量适用规则；不允许任意互换。
- 完成深空霓虹、玻璃柔光、数据编辑部、企业极简四个主题，以及 Logo、品牌色、明暗倾向和受控字体组成的品牌预设。
- ECharts 负责数据编码并优先 SVG；Canvas 模式保留等价文字摘要。Three.js／React Three Fiber 只提供延迟加载的视觉场景，先有完整二维内容，再按能力渐进增强。

**M3-E2：发布包与观看端交互**

- 从发布前故事版本生成最小交互数据包，只携带获准筛选重算所需版本化累加器、叙事规则和所有者明确选择的明细；观看端复用 M1 的 `metric-runtime`。
- creator/viewer 共享 `story-package-v1` codec；只有交互 entry 使用固定单 member gzip，stored ≤5 MB、decoded ≤32 MiB，全部 entry decoded 总量 ≤64 MiB，完整加密 frame ≤10 MB。观看端外层认证后流式有界解压并验证长度、CRC、hash 与 Schema；超限时只允许显式降低时间粒度、移除高基数筛选、合并长尾或关闭次要交互。
- `COUNT_DISTINCT` 的观看交互使用发布内稳定、每次发布重新随机映射且不含原值／映射的临时 token 压缩精确集合／位图；按筛选原子格求并集，不相加分组去重数、不做近似。预览明确该机制不保证抵御基于出现模式和外部知识的跨发布关联／再识别；超出 5 MB 或披露风险不可接受时，强制关闭受影响筛选或把指标／区块显式设为不联动。
- 观看端本地筛选、重新聚合并更新／隐藏／标记不适用结论，不调用 AI，不提供未发布数据的下钻、搜索或下载。
- 明细发布前展示真实值、字段与记录范围并二次确认；含直接标识或机密字段时强制密码和有效期。

**M3-E3：端到端加密与密码分享**

- 先取得发布 ID／到期信息，再生成随机 256 位分享密钥；以 12 字节随机 nonce、128 位 tag 的 AES-256-GCM 加密整个发布包，JCS AAD 绑定用途、协议、Schema、发布 ID 与到期信息。
- 无密码分享使用版本化 Fragment 携带分享密钥；带密码分享只携带 `a2id-v1-64m-t3-p1` profile ID、16 字节盐、12 字节包裹 nonce 和 AES-256-GCM 包裹后的分享密钥，绝不携带裸密钥或任意 KDF 参数。
- Fragment 在 KDF 前执行 2,048 字符、版本、profile、Schema 和字段长度硬校验；项目包使用相同 KDF 但独立 package key、purpose 与 4 KiB 头上限，禁止协议材料互换。
- 默认生成高熵密码；自定义口令至少 12 个字符并提示离线猜测风险。密码、派生密钥和分享密钥不发送服务器。
- 每个发布生成仅本地保存的发布管理凭证；明确提示撤销只能阻止后续下载，不能收回已下载、复制或截图内容。

**M3-E4：临时分享与滥用控制服务**

- 用 Hono 无状态服务完成发布、下载、撤销和过期；加密发布包存 OSS，Tair 仅保存最长 24 小时的到期／撤销状态、发布管理凭证校验值、流量计数、限流键和工作量证明 nonce。
- 落实官方配额：同一来源 5 次／10 分钟、30 次／24 小时；观看 120 次／分钟；单分享生命周期 10 GB 下行并在 80% 预警。
- 来源地址只以每日轮换密钥生成 HMAC 限流键；异常发布使用浏览器计算型工作量证明，不使用第三方验证码、Cookie 或设备指纹。
- 管理员只能按举报删除指定密文；观看端在独立 Origin 先认证解密、再校验版本化 Schema，并执行严格 CSP，拒绝任意 HTML、JavaScript 和可执行附件。

**M3-E5：静态导出与无障碍发布校验**

- 在创作端浏览器本地生成完整故事 PDF 和逐区块 PNG；动效选择确定性静态关键帧，不上传未发布内容。
- 发布前强制检查数值／证据、Schema、访问保护、文字对比、非颜色区分、键盘、焦点、等价描述和弱动效。
- 不合格主题或品牌色自动调整衍生参数以达到 WCAG 2.2 AA 核心要求，不提供绕过按钮。

**M3-E6：可选且无内容的遥测**

- 官方实例只在用户以同等醒目的选项明确同意后发送阶段、耗时区间、数据规模区间、文件类型、成功状态和标准错误码；自托管默认关闭。
- 会话随机标识不跨会话；不使用 Cookie、设备指纹或第三方追踪，不采集任何文件、字段、数据、证据、提示词、故事、模型配置、分享或项目标识。

### 6.4 交付物

- 全部首批区块、四主题、品牌预设、响应式布局和二维／3D 降级 Storybook 矩阵。
- 创作端发布校验、发布包预览、密码分享和撤销管理界面。
- 轻量观看端、临时分享服务、Tair／Valkey 状态实现和公开配额配置。
- 浏览器本地 PDF／PNG 导出。
- 加密协议版本说明，以及覆盖 KDF、JCS、AES-GCM 内容／包裹、base64url、Unicode 口令、错误／篡改／超限的互操作夹具和内容安全／删除边界文档。

### 6.5 强制验证

- 无密码和带密码分享都能发布、下载、解密、交互、撤销和自然到期；固定向量在 creator/viewer 与支持浏览器互操作，服务器及日志无法获得明文、密码、KEK 或分享密钥。
- 受保护明细在缺少密码或有效期时无法发布；普通明细只包含用户明确确认的字段和值。
- 交互改变后，指标与图表按时延预算重算，精确 `COUNT_DISTINCT` 跨时间／分类多选结果与创作端黄金值一致，失效结论正确隐藏或标记；观看端网络记录中没有模型调用。
- `COUNT_DISTINCT` 精确状态超出 5 MB 或未通过披露检查时，受影响交互按发布预览选择关闭且无原始标识 token 映射；任何路径都不能近似或相加分组去重数。
- 发布 frame／container／固定 gzip 互操作、压缩炸弹／多 member／尾随／长度与 hash 异常、包体、发布频率、观看频率、流量、80% 预警、工作量证明和 24 小时 TTL 都有确定性测试。
- 四主题、首批区块、桌面／平板／手机断点和二维回退进入视觉回归；截图固定随机种子并关闭动效。
- PDF／PNG 在支持的创作浏览器中本地生成；WebGL、弱动效或必要加密能力缺失时按既定方式二维回退或明确要求更换浏览器，绝不降级明文。

### 6.6 退出标准

- 项目所有者可以从 M1/M2 草稿创建不可变故事版本，完成发布校验并生成可打开、可撤销、最多存在 24 小时的分享链接，或生成本地 PDF／PNG。
- 分享云端只包含密文和 ADR-0046 允许的 TTL 运行状态；生命周期与定时清理双路径通过验证。
- 全部首批区块、四主题、品牌预设、观看交互、明细保护、2D 回退和静态导出均通过当前强制门槛。
- 任何失败路径都不会上传原始表、关闭加密、绕过密码保护或延长官方内容留存。

### 6.7 风险与回退

| 风险 | 回退 |
|---|---|
| WebGL／移动 GPU 性能不足 | 自动使用 CSS／SVG 二维场景和弱动效；信息必须完整保留 |
| 交互 entry stored 超过 5 MB／decoded 超过 32 MiB、全部 entry decoded 超过 64 MiB、总 frame 超过 10 MB 或精确去重状态披露风险过高 | 要求用户显式降低粒度、移除高基数筛选、合并长尾、关闭受影响筛选或把指标设为不联动；不放宽解码上限、不抽样、不近似、不上传原始表 |
| 设备缺少必要 Web Crypto／Argon2id 能力 | 明确提示使用受支持浏览器；不提供明文分享 |
| 本地导出出现浏览器字体／分页差异 | 限定并测试已声明的 Chrome／Edge 创作范围；不切换为云端渲染 |

## 7. M4：公开 MVP

### 7.1 目标

对完整产品执行兼容性、迁移、性能、视觉、无障碍、安全、供应商、临时云和社区自部署认证；以本地自动化闭环语料库替代当前无法实施的大规模用户测试发布门槛，并发布可复现的公开 MVP。

### 7.2 依赖

- M0–M3 的所有退出标准已满足。
- 候选版本已冻结 Schema、协议、模型目录版本、基础设施配置和公开文档内容；此后只允许修复发布阻塞项。

### 7.3 工作包／Epic

**M4-E1：本地自动化闭环语料库**

- 至少维护 30 份具有确切预期结果的人工黄金表格。
- 至少生成 200 份确定性的有效表格，覆盖受支持格式、编码、字段角色、时间、币种、单位、缺失、重复、异常、长尾、样本和布局组合。
- 至少维护 100 份格式错误、超限、压缩炸弹及其他资源／边界攻击无效表格。
- 至少运行 1,000 组随机种子的指标性质测试，验证聚合、筛选、表达式、单位、币种、除零、时间比较和证据不变量。
- 全部语料只在本地浏览器和 CI 中运行，不上传官方实例。

**M4-E2：完整质量矩阵**

- 数值、Schema／永久迁移、视觉、无障碍、核心端到端和性能预算六类门槛全部强制执行。
- 为 `metric-runtime` 增加跨时间／分类单选、多选和组合筛选黄金矩阵，逐值对比 creator 与 viewer；`COUNT_DISTINCT` 必须验证精确 token 集合并集、原值／映射缺失及超限后关闭交互的行为。
- 固定小型、常见档、20 万行窄表、50 MB／100 列较短宽表基准；绝对时延达标且相对 `main` 多次运行中位数退化不超过 15%。
- 视觉矩阵覆盖四主题、主要区块、桌面／平板／手机、二维回退；有意变化与基线在同一 PR 审查，禁止批量重录掩盖回归。
- 对当前与上一主版本观看兼容、所有正式历史项目逐步迁移、项目包往返和失败保留原项目执行全量验证。
- 以跨越多个 1 MiB 分块的大型项目夹具验证流式内存边界、KDF 前 4 GiB／framing 拒绝、首块认证后且分配／解析前的 manifest 上限拒绝、分块重排／截断／尾随拒绝和 OPFS 暂存原子提交。

**M4-E3：真实浏览器与设备认证**

- Playwright Chromium／WebKit 继续承担自动近似验证。
- 官方托管版本发布前，按公开清单在所声明版本的真实 macOS／iOS Safari 和 Android／iOS 主流微信内置浏览器上检查：链接打开、Schema 校验、下载、Web Crypto 解密、密码解包、筛选交互、键盘／触摸、弱动效、二维回退和可读性。
- 保存设备／系统／浏览器版本、检查结果和已知限制；必要能力缺失时只提示换用受支持浏览器，不降级明文。

**M4-E4：真实供应商、条款与中国网络认证**

- 用维护方真实密钥和最小合成数据验证百炼北京 Workspace、北京 Key、专属域名与候选目录模型；验证 `json_object`、“JSON”提示约束、错误分类和一次修复路径。
- 用 Glosc 真实密钥验证 `/models`、所选模型的基础调用、`json_object`、流式 SSE／usage 和错误；未通过的能力保持关闭或回退非流式。
- 检查真实请求期间的代理日志、APM、错误追踪、访问日志和前端崩溃报告，确认没有 Authorization 或证据包。
- 从目标中国大陆运营商／地区实测两家供应商的 DNS、TLS、首 Token 时延和完整响应；Glosc 未通过前不得宣传中国大陆稳定可用或境内驻留。
- 核对并在配置页提供当前服务条款／隐私政策链接，确认请求响应留存、训练用途、上游／分包商、数据地域和删除机制；未获明确依据的事项继续标为“供应商未公开／待确认”。以真实证据包调用验证首次调用前必须确认，条款版本／链接变化会使确认失效并要求重确认，且确认记录只在本地。

**M4-E5：官方临时云与隐私认证**

- 验证北京 OSS/CDN、函数计算／API 网关、密文 Bucket、Tair 强制 TTL、生命周期与定时清理；CDN 不长期缓存快照。
- 验证撤销原子性、10 GB 生命周期流量、80% 预警、所有限流、每日轮换 HMAC 和工作量证明；对过期对象及状态执行超过承诺窗口的残留检查。
- 验证遥测默认关闭、同意／拒绝同等显著、会话 ID 不跨会话、内容字段永不采集、IP 原始日志 ≤ 24 小时、匿名事件 ≤ 30 天且仅最小样本汇总可长期保存。
- 执行发布 frame／受控容器／固定 gzip／压缩炸弹与 decoded 上限、项目包固定加密向量与解析上限、四 Origin 存储／CryptoKey／Service Worker 否定测试、Worker 禁网、连接器独占可注册域与加载前 `Clear-Site-Data`／其他应用 Cookie 不受影响／跨请求无残留／伪造与重放消息、逐路由 CORS、CSP、任意 HTML／脚本拒绝、密钥／日志泄漏和受保护明细发布校验的安全验证。

**M4-E6：社区自部署与文档**

- 从干净环境依据公开文档部署四个独立 Origin 且连接器安全纪元使用独占可注册域的社区参考实例，以 Valkey 提供 TTL 状态并使用自托管者配置的对象存储／运行环境；单 Origin 路径部署必须在启动检查中明确拒绝，无法为连接器提供独占可注册域时必须禁用自定义连接器，不能通过移除 `Clear-Site-Data: "cookies"` 后在共享可注册域继续启用。
- 冒烟完成静态资源加载、加密发布包上传、观看端下载／解密、撤销、过期清理、公开配额修改和遥测默认关闭。
- 完成开发、构建、测试、数据边界、模型配置、官方实例隐私、项目备份恢复、社区自部署、升级／迁移、故障排查和安全假设文档。
- 明确社区参考不构成企业私有化交付、迁移服务、技术支持或 SLA。

**M4-E7：可复现发布**

- 所有候选变更经受保护 `main`、merge queue 和敏感路径复核；用户可见变化带 Changeset。
- GitHub Actions 根据 SemVer 标签生成 Release、变更日志、构建产物、校验和与 SBOM；禁止个人设备手工上传正式产物。
- 紧急流程不得绕过任何数值、迁移、视觉、无障碍、端到端或性能门槛。

### 7.4 交付物

- 版本化本地测试语料库、随机性质测试和完整候选版本质量报告。
- 真实 Safari／微信设备检查记录，以及真实百炼／Glosc／中国网络／条款检查记录。
- 官方北京部署验证报告和社区自部署冒烟记录。

### 7.5 强制验证

- 30 份黄金表格和 200 份有效表格必须 100% 完成“导入 → 生成 → 修改时间范围 → 联动重算 → 发布或导出”，并满足确切数值预期与时延预算。
- 100 份无效表格必须 100% 明确拒绝，不崩溃、挂起、抽样、截断或转云端。
- 1,000 组随机种子性质测试全部满足指标和证据不变量，creator/viewer 精确去重黄金矩阵全部一致；失败种子必须可复现并进入回归集。
- 模拟／录制 AI 契约、两家预设供应商的基础真实冒烟、正式浏览器矩阵的基础观看流程和社区自部署冒烟必须全部通过。只有流式、原生 JSON Mode、3D 氛围等明确标为可选／渐进增强的子能力可在关闭后重新验证；不得通过删除百炼／Glosc 预设、Safari／微信必选版本或基础加密／筛选能力绕过发布门槛。

### 7.6 退出标准

- M4-E1 至 M4-E7 及每项当前有效、未被取代的 ADR 全部有可审计实现证据，正式构建只由 GitHub Actions 从受保护标签产生。
- 官方实例的数据驻留、密文、TTL、限流、遥测和日志承诺与代码／配置／运行结果一致。
- 公开浏览器、供应商与自部署声明不超过真实验证范围；未核实的第三方留存、训练、SLA 或地域事实被明确标注。

- GitHub Release、校验和、SBOM、升级说明和社区部署说明均可公开获取，公开 MVP 才可发布。

## 8. 关键路径

以下顺序决定 MVP 能否成立；后项不能用临时私有协议绕过前项：

1. **领域语义与故事 Schema** → 所有数据、编辑、迁移、AI、渲染和发布契约。
2. **浏览器本地分析与资源准入** → 确定可兑现的输入上限、数值语义和性能预算。
3. **基础生成、编辑联动与版本生命周期** → 证明无 AI 的核心产品闭环。
4. **证据包与模型配置** → 在不外发原始数据、不允许模型改数值的前提下加入 AI 增强。
5. **交互数据包、加密协议与观看器** → 形成安全、可撤销、可到期的分享闭环。
6. **全量语料与外部认证** → 真实供应商、Safari／微信、官方临时云和社区自部署共同决定公开发布。

任何关键路径上的 Schema、数值、迁移、加密或数据驻留失败都是发布阻塞项。

## 9. 可并行机会

并行以共享契约稳定为前提，不假定需要特定人数：

- M0 中，CI／治理、部署骨架和性能夹具可以并行推进，但共同依赖初始 Schema 与数据契约。
- 本地测试语料库从 M0 开始持续积累；黄金预期随 M1 数值语义固化，供应商录制响应随 M2 适配器固化，M4 只执行完整强制矩阵。
- M1 的质量规则／指标引擎与编辑器外壳可并行，以同一证据引用和分析条件契约集成。
- M2 的三个供应商适配器可按统一内部 DTO 并行；证据包和代理日志脱敏必须先形成共同门槛。
- M3 的故事区块／主题 Storybook、观看端、分享服务和静态导出可并行；集成前必须共享 Schema、交互数据包和加密协议版本。
- 文档、迁移历史样本、视觉基线、真实设备清单、供应商检查清单和社区冒烟脚本应随功能同步维护，不集中到发布前补写。

## 10. MVP 延后项

以下范围在 M0–M4 中不实施；新增需求只能等量替换既有范围后重新评估路线图：

- 实时／定时刷新、流式数据、数据库或 SaaS 数据源。
- 多表关联、数据仓库建模、跨项目合并。
- 账号、多人协作、评论、云同步、SSO、RBAC、永久分享。
- 任意 SQL／Python／JavaScript、插件代码、文本公式、自由画布。
- 预测、因果推断、AI 编造的行业基准或自动经营决策。
- 地图、桑基、网络、雷达、仪表盘、漏斗和 3D 数据编码。
- PPTX、视频、GIF、可编辑设计文件和原始数据下载。
- 手机创作、原生桌面／移动应用、Firefox 创作端和旧版浏览器。
- 英文、多地区数据驻留、企业私有化交付与专属 SLA。
- 云端原始数据分析、平台公共 AI 额度、自定义端点代理和手填模型 ID。
