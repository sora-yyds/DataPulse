## 2. 愿景与问题

DataPulse AI 面向临时收到汇报任务、需要快速把一份业务表格转成管理层材料的运营、市场和商业分析人员。现有做法往往要求先理解字段、清洗数据、计算指标、选择图表、排版、撰写结论，再解决分享与导出，时间紧张时容易出现口径错误、视觉粗糙、结论与筛选状态不一致等问题。

产品愿景是：用户导入一份规范单表后，一键获得一份具有现代设计感、数值可验证、可直接编辑、可安全分享的响应式数据故事；即使没有模型密钥，也能完成基础生成。DataPulse AI 不是实时 BI，也不以 3D 效果替代正确的数据表达。

## 3. 目标用户与 JTBD

### 3.1 主要用户

**汇报制作者／项目所有者**：需要向管理层或内部协作方汇报业务结果的运营、市场或商业分析人员；能够访问本地项目的人即拥有该项目的编辑、发布、撤销和删除能力。

MVP 的免账号、本地所有权与无法找回边界见 [ADR-0018](adr/0018-no-accounts-local-ownership.md)。

核心 JTBD：

> 当我拿到一份结构化业务表并需要尽快汇报时，我希望系统自动完成可靠分析、故事组织和高质量视觉设计，同时允许我直接修改时间范围、口径、图表和文案，使全部关联内容一致更新，并能在明确数据暴露范围后生成链接或静态文件。

### 3.2 次要用户

**观看者**：通过免登录分享链接查看固定发布快照，并在发布者允许的维度内筛选。观看者不能编辑故事、访问未发布数据或下载原始数据集。

> 当我收到一份汇报链接时，我希望在常用浏览器或微信中直接阅读，并在获准范围内调整时间、地区或品类，看到指标、图表和结论同步变化。

## 4. 产品目标与原则

### 4.1 MVP 目标

- 从单个 Excel 或 CSV 形成一份通常包含 4–8 个区块的完整、可编辑数据故事。
- 在模型不可用或用户未配置密钥时，仍提供确定性的基础生成闭环。
- 所有数值、比较和评价性结论均可追溯、可复算，不预测、不声称因果。
- 让时间范围、分析条件和受控指标编辑驱动指标、图表与叙事一致更新。
- 原始数据在浏览器内分析；仅经用户确认的证据包、发布内容或选定明细可离开设备。
- 提供有设计感但可降级、可访问、可测试的响应式滚动故事。
- 以临时、端到端加密的分享和本地静态导出支持分发。

### 4.2 产品原则

1. **正确性优先**：没有足够证据时生成受限草稿，不填充看似完整但不可证明的内容。
2. **本地优先**：解析、质量检查、分析、指标计算和静态导出在浏览器内完成，不做云端原始数据回退。
3. **AI 组织表达，不计算事实**：模型只读取证据包，指标和判定由确定性引擎执行。
4. **一键完成，成品可编辑**：直接控件为主，自然语言编辑为辅；修改必须可见、可撤销并联动更新。
5. **受控设计系统**：AI 产出故事蓝图，渲染器只接受已验证区块、图表、主题和动效，不执行任意代码。
6. **发布即知情披露**：发布者可以分享真实明细，但必须预览实际值、明确范围并承担决定；受保护明细强制更严格保护。
7. **临时云端**：官方实例不保存长期用户项目，仅保存最长 24 小时的加密发布包和严格限时运行状态。
8. **开放可审计**：全栈、Schema、分析规则、部署和质量门槛均在 GitHub 公开，应用采用 AGPL-3.0。

## 5. 核心端到端流程

### 5.1 首次生成

1. 制作者在本地创建项目并选择 `.xlsx` 或 CSV。
2. 系统验证格式、大小、行列数、非空单元格、压缩比和预计内存；不合格时明确拒绝。
3. 用户明确选定要形成规范单表的工作表／记录范围；系统不沿用隐藏行状态做静默排除。
4. 浏览器工作线程解析数据、推断字段角色、展示质量问题和分析假设，用户可纠正。
5. 本地分析引擎计算指标、比较、异常候选和证据，生成完整基础故事或说明限制的受限草稿。
6. 用户可选择配置 BYOK 并基于可预览的证据包执行 AI 增强。
7. 用户通过直接控件或自然语言编辑；时间范围等变化触发确定性联动重算。
8. 用户通过发布校验后，生成最长 24 小时的加密分享链接，或在本地导出 PDF／PNG。

### 5.2 更新数据

1. 用户为同一数据集导入新文件，形成新的不可变数据集版本。
2. 如字段结构变化，系统要求确认映射；不得静默把旧字段绑定到新字段。
3. 更换数据前若草稿有未固化修改，先创建故事版本。
4. 系统复用汇报目标、指标、布局、主题和品牌设置，在新数据上重新生成；完成后创建新故事版本。
5. 历史数据集版本、故事版本和既有发布快照保持可复现，不被覆盖。

数据更新的版本原则见 [ADR-0003](adr/0003-version-data-story-updates.md) 与 [ADR-0048](adr/0048-explicit-story-version-checkpoints.md)。

### 5.3 观看与探索

1. 观看者打开不可猜测且不可索引的链接，下载加密发布包并在浏览器解密。
2. 若为密码分享，观看者在本地输入密码并解包分享密钥；密码不发送服务器。
3. 观看者在获准分析条件内探索，形成仅属于当前观看者的探索会话。
4. 观看端使用交互数据包重算指标与图表，并用叙事规则更新、隐藏或标记失效结论；全程不调用 AI。

## 6. 详细功能需求

### 6.1 项目与本地持久化

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| FR-PROJ-001 | MVP 不要求注册或登录；项目只存在于当前浏览器。 | 断网且无账号状态仍可创建、打开和编辑本地项目。 |
| FR-PROJ-002 | 项目必须长期保存数据集版本、故事蓝图、草稿、故事版本和品牌预设。 | 重启浏览器后项目可恢复到最后自动保存草稿。 |
| FR-PROJ-003 | 元数据和索引保存于 IndexedDB；加密数据集、Arrow 数据和大型资源保存于 OPFS；不得以 `localStorage` 保存数据或密钥。 | 存储检查中无项目数据或密钥出现在 `localStorage`。 |
| FR-PROJ-004 | 首次创建项目时请求持久存储；导入或新增版本前检查配额。 | 空间不足时阻止操作并要求用户删除版本或导出备份，不自动清理。 |
| FR-PROJ-005 | 本地内容使用设备绑定、不可导出的 Web Crypto 密钥加密。 | 直接复制本地持久化文件不能在另一浏览器配置中解密。 |
| FR-PROJ-006 | 项目包必须使用用途隔离的版本化密码加密信封：随机 256 位包密钥加密内容，Argon2id 只派生用于包裹包密钥的 KEK；项目包包含数据集、蓝图、版本、草稿和品牌预设。 | 固定互操作、错误、篡改和超限向量跨支持浏览器通过；导出包不包含模型凭据和既有发布管理凭证，导入后需重新配置模型并重新发布。 |
| FR-PROJ-007 | 产品必须明确提示清除站点数据会同时销毁本地项目和设备密钥，平台不能恢复。 | 清除站点数据后无账号恢复或云端副本入口。 |
| FR-PROJ-008 | `project-envelope-v1` 必须以固定 1 MiB AES-GCM 认证分块流式导出／导入，明文 payload ≤4 GiB、受控 manifest ≤1 MiB 且不使用二次压缩；超限项目要求先减少版本或资源。 | 大包测试不分配整包内存；header、profile、文件／分块 framing、计数及 4 GiB 声明上限在 KDF 前校验；manifest 长度在 KDF 和首块认证解密后读取，并在分配或解析 manifest 前校验 ≤1 MiB 及不超过剩余 payload。导入只在全部 tag 与哈希通过后原子提交，失败不替换最后可读项目。 |
| FR-PROJ-009 | 完整项目的预计项目包明文 payload 必须始终 ≤4 GiB；导入新数据版本或新增资源前同时检查浏览器配额与完整可备份大小，不得先写入一个无法导出完整项目包的合法状态。 | 超限操作在提交前被阻止，并允许所有者先导出当前完整项目，再删除版本／资源或创建新项目；已有故事版本不被静默丢弃。 |

### 6.2 输入契约与导入

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| FR-IMP-001 | 一次导入只形成一个规范数据表，每行代表一条同类业务记录；MVP 不做多表关联。 | 多工作表不会自动合并；生成只绑定一个明确导入范围。 |
| FR-IMP-002 | 支持 `.xlsx`，不支持 `.xls`、`.xlsm`、`.ods`。 | 不支持格式在解析前被明确拒绝。 |
| FR-IMP-003 | 支持 UTF-8、GBK、GB18030 编码的 CSV。 | 三类编码夹具可正确解析中文字段和值。 |
| FR-IMP-004 | Excel 只读取工作表、显示格式和缓存公式结果，不执行公式或宏。 | 导入不会运行工作簿公式、宏或外部链接；只有现有缓存结果可作为值。 |
| FR-IMP-005 | 原文件只由 File API 瞬时读取；解析完成后释放 Blob 引用，不将原文件写入本地项目或上传云端。 | 本地存储和网络记录中均不存在原始文件 Blob。 |
| FR-IMP-006 | 输入必须同时满足：文件 ≤50 MB、行 ≤200,000、列 ≤100、非空单元格 ≤5,000,000。 | 任一维度超限均返回具体原因。 |
| FR-IMP-007 | `.xlsx` 解压内容必须 ≤500 MB 且压缩比 ≤100:1。 | 压缩炸弹夹具在解析内容前或安全边界内被拒绝。 |
| FR-IMP-008 | 导入前估算峰值工作内存，预计超过 1.5 GB 时拒绝。 | 拒绝信息说明是内存准入条件，而非笼统“导入失败”。 |
| FR-IMP-009 | 行数与列数上限是独立外边界，不承诺 200,000 行与 100 列同时满载。 | UI 同时展示全部适用的准入条件。 |
| FR-IMP-010 | 超限或资源不足时不得静默抽样、截断、删列或转为云端处理。 | 测试中输入要么完整导入，要么明确拒绝。 |
| FR-IMP-011 | 每次成功导入形成不可变数据集版本；原数据值不得被后续清洗或编辑覆盖。 | 任一处理均表现为可追溯分析处理，新导入不会修改旧版本。 |
| FR-IMP-012 | 更新数据发生字段结构变化时必须展示并确认映射。 | 未确认前不得复用旧指标或图表绑定完成生成。 |

输入上限的参考创作设备为 4 核 CPU、8 GB 内存、集成显卡、最新稳定版 Chrome／Edge。M0 必须在真实参考环境验证公开上限；若不能满足三分钟边界档目标，必须在 M1 前下调公开上限，不能发布无法兑现的规格。参见 [ADR-0050](adr/0050-resource-aware-local-import-limits.md)。

### 6.3 字段角色、质量检查与分析处理

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| FR-DATA-001 | 系统必须推断并允许用户纠正六类字段角色：时间、分类维度、数值度量、唯一标识、自由文本、直接标识。 | 角色更改可见，并触发依赖指标、证据和故事重算。 |
| FR-DATA-002 | 机密性是所有者主动添加的标记，不是第七种字段角色；系统不得宣称能自动发现所有商业机密。 | UI 文案区分“直接标识提示”与“所有者标记的机密”。 |
| FR-DATA-003 | 直接标识可依据字段名和内容模式提示，所有者可纠正。 | 手机号、邮箱等夹具有提示，同时允许取消误判。 |
| FR-DATA-004 | 缺失值默认从对应计算的有效样本中排除，并展示缺失率；不得自动补零。 | 指标证据同时包含有效样本量和缺失率。 |
| FR-DATA-005 | 重复记录只提示；只有所有者明确选择判重字段后才能形成可撤销的排除规则。 | 未配置判重规则时，相同行仍参与计算。 |
| FR-DATA-006 | 异常值只标记，不自动排除或更改有效样本。 | 异常标记前后指标结果一致，除非用户另行应用可见处理。 |
| FR-DATA-007 | 分类默认展示当前指标下 Top 8，其余显式聚合为“其他”，并说明被合并的分类项数量。 | 图表和证据不静默丢弃长尾项。 |
| FR-DATA-008 | 所有清洗、排除、转换和分析假设必须可见、可追溯、可撤销。 | 撤销处理后依赖指标与故事恢复到处理前状态。 |

### 6.4 分析正确性与指标

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| FR-ANA-001 | 故事时区默认 `Asia/Shanghai`；无时区时间必须形成可见、可编辑的分析假设。 | 更改时区假设后所有依赖时间聚合重算。 |
| FR-ANA-002 | 系统必须识别并展示数据截止点；未完整周期只允许与基准周期的相同进度比较。 | 不出现“部分本期 vs 完整上期／去年同期”的百分比结论。 |
| FR-ANA-003 | 多币种必须分开分析，不得自动换汇或形成混合币种总额。 | CNY 与 USD 不能直接相加；需要换汇的口径被拒绝。 |
| FR-ANA-004 | 指标必须显式记录计量单位；货币指标还必须记录币种。“万／亿”只作为显示尺度。 | 改变显示尺度不改变底层值、单位或币种。 |
| FR-ANA-005 | 基期为零时不得输出百分比变化，必须显示“不可用”及原因。 | 零基期夹具中无无穷大或误导百分比。 |
| FR-ANA-006 | 有效样本少于 30 条时标记为小样本，禁止强结论；分组比较任一组少于 30 条即触发。 | 叙事显示限制，不使用确定性评价语言。 |
| FR-ANA-007 | 比较基准只能来自上期、去年同期、数据内对照组或所有者提供的目标。 | 模型或基础生成不能创建无来源行业均值与目标。 |
| FR-ANA-008 | 只允许陈述可计算的事实、趋势、异常和贡献；不得预测，不得把相关性写成因果。 | 规则与生成测试拒绝预测字段和因果措辞。 |
| FR-ANA-009 | 每项数值陈述必须绑定指标、证据或分析条件 ID；评价性语言必须绑定阈值、排名、统计方法或业务基准。 | 未知引用、硬编码额外数字或无规则评价导致蓝图校验失败。 |
| FR-ANA-010 | 数据质量或证据不足时生成受限草稿并说明具体限制，不以低质量区块凑足数量。 | 极少字段／小样本夹具得到明确受限状态，而非虚构结论。 |
| FR-ANA-011 | 指标计算必须始终由确定性本地分析引擎执行，AI 不得重新计算或覆盖结果。 | 相同数据、条件和指标定义在基础生成与 AI 增强前后数值一致。 |

### 6.5 受控自定义指标

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| FR-MET-001 | MVP 只提供可视化指标构建器，不允许输入公式文本。 | UI 和导入协议均无 SQL、Python、JavaScript 或文本公式执行入口。 |
| FR-MET-002 | 基础聚合限于 `SUM`、`AVG`、`MIN`、`MAX`、`COUNT_ROWS`、`COUNT_VALID`、`COUNT_DISTINCT`。 | Schema 拒绝枚举外聚合。 |
| FR-MET-003 | 每个基础指标可附加受控指标条件。 | 条件范围和有效样本可在指标详情中检查。 |
| FR-MET-004 | 派生指标只允许指标引用、数值常量、括号和 `+ - × ÷`，并支持内置环比、同比和目标差异。 | 表达式保存为可检查、可迁移的树而非代码字符串。 |
| FR-MET-005 | 加减要求单位与币种兼容；乘除推导比例或复合单位。 | 不兼容运算在保存前被阻止并说明原因。 |
| FR-MET-006 | 除零返回带原因的“不可用”，不得返回 0 或无穷大。 | 性质测试覆盖零分母。 |
| FR-MET-007 | AI 可提议指标树，但所有者必须确认聚合、筛选、单位和口径后方可采用。 | 未确认提议不进入当前草稿计算。 |
| FR-MET-008 | 不支持行级计算列、窗口函数、条件表达式、跨数据集计算或任意 SQL。 | Schema、UI 和执行层均拒绝这些能力。 |
| FR-MET-009 | 创作端与观看端必须复用同一纯确定性指标运行时和版本化累加器语义；`AVG` 以 `sum + count` 合并，`COUNT_DISTINCT` 以精确集合并集计算。 | 跨筛选黄金测试中两端逐值一致；不得把分组去重数相加或把精确结果静默改成近似值。 |

### 6.6 基础生成与 AI 增强

| 编号 | 需求 | 可验证结果 |
|---|---|---|

| SEC-007 | 产品不得声称本地加密能抵御已取得浏览器执行权限的恶意扩展、设备恶意软件或同源 XSS。 | 安全说明披露威胁边界，并配合 CSP 与依赖治理。 |
| SEC-008 | 官方实例和社区参考部署必须把创作端、观看端、API 与自定义连接器放在四个独立 Origin；不得以同一 Origin 的不同路径替代隔离。连接器的每个安全纪元必须使用不承载其他应用的独占可注册域；DataPulse 页面与 API 不使用 Cookie，基础设施不可避免的 Cookie 必须全部使用 `__Host-` 前缀并满足 `Secure; Path=/`、无 `Domain`。不能提供独占可注册域的自托管部署必须禁用自定义连接器。 | 跨 Origin 否定测试证明观看端和连接器不能读取创作端 IndexedDB、OPFS、CryptoKey、`__Host-` Cookie 或 Service Worker 状态；连接器的 Cookie 清理不会清除或改变其他应用状态。测试明确验证 host-bound Cookie，且不得把不同端口误当作 Cookie 隔离。 |

| SEC-010 | 创作端 CSP 只允许连接固定官方 API，观看端只允许下载所需 API，自定义连接器才可连接经校验的 HTTPS／localhost 端点；API CORS 必须按路由精确允许创作端或观看端 Origin，禁止通配符。 | 响应头与浏览器测试证明任意外部连接、跨端 API 调用和宽松 CORS 均被拒绝。 |

| PRIV-003 | 获准事件只含阶段、耗时区间、规模区间、文件类型、成功状态、标准错误码和仅当前会话随机 ID。 | 事件 Schema 不接受内容字段或跨会话标识。 |
| PRIV-004 | 永不采集文件名、字段名、分类值、原始数据、证据包、提示词、故事内容、模型配置、分享信息或本地项目 ID；不得使用 Cookie、设备指纹或第三方行为追踪。 | 自动内容扫描和依赖检查通过。 |
| PRIV-005 | IP 原始日志最长 24 小时，匿名事件最长 30 天；仅达到最小样本量的汇总指标可长期保存。 | 生命周期策略和删除验证可审计。 |
| PRIV-006 | 遥测协议、实现和关闭方式必须开源；遥测不得被表述为十分钟可用性假设的证明。 | 产品文案与报告不将遥测通过率等同用户成功率。 |

### 7.3 匿名分享配额与滥用控制

| 编号 | 需求 | 可验证结果 |
|---|---|---|
| OPS-001 | 官方实例单个加密发布包 ≤10 MB，其中交互数据包 ≤5 MB。 | 超限发布被明确拒绝。 |
| OPS-002 | 同一来源最多发布 5 次／10 分钟、30 次／24 小时；观看请求 120 次／分钟。 | 边界内成功，超额返回可解释限流状态。 |
| OPS-003 | 单个分享生命周期内最多 10 GB 下行，达到 80% 在本地管理页预警，达到上限停止下载。 | 计数、预警和封顶均可复现。 |
| OPS-004 | 异常发布使用浏览器计算型工作量证明，不接入第三方验证码、Cookie 或设备指纹。 | 触发后只产生短期 nonce 和证明校验。 |
| OPS-005 | 管理员可按举报删除指定密文对象，但无法解密或检查内容。 | 删除操作只需要对象标识，不提供服务端内容查看入口。 |

## 10. MVP 范围与里程碑

| 里程碑 | 必须形成的可运行纵向切片 |

| M0 工程底座 | monorepo、故事 Schema、合成夹具、CI、迁移框架、本地加密存储、部署底座；真实 Chrome／Edge 验证资源上限，最小真实 iOS Safari／Android 微信／iOS 微信探针冻结加密 profile。 |

| M2 AI 增强 Beta | 证据包预览、百炼／Glosc／自定义端点、模型目录、结构化生成与一次修复、确定性叙事规则。 |

## 11. 明确非目标

以下项目不进入 MVP，属于延期而非永久禁止：

- 实时大屏、定时刷新、流式数据、数据库或 SaaS 数据源连接；
- 多表关联、数据仓库建模、跨项目数据合并；
- 账号、多人协作、评论、云端项目同步、SSO、RBAC、永久分享；
- 任意 SQL、Python、JavaScript、插件代码、无限制公式、自由画布；
- 预测、因果推断、AI 编造行业基准、自动经营决策；
- 地图、桑基、网络、雷达、仪表盘、漏斗及 3D 数据图表；
- PPTX、视频、GIF、可编辑设计文件、原始数据下载；
- 手机创作、原生桌面／移动应用、Firefox 创作端、旧版浏览器；
- 英文界面、多地区数据驻留、企业私有化交付、专属 SLA；
- 云端原始数据分析、平台公共 AI 额度、自定义端点代理、手填模型 ID。

MVP 开发期间，新增需求只有在替换同等工作量的既有范围时才能进入，不能单纯追加。参见 [ADR-0044](adr/0044-freeze-mvp-boundaries.md)。

## 12. 成功假设与 MVP 自动化验收

### 12.1 尚未验证的产品假设

“十分钟可分享成果率”指目标汇报制作者从开始导入到无人工协助形成分享链接或静态副本不超过十分钟的比例。它目前只是待真实用户研究验证的产品假设：

- 不得对外宣称该目标已经达到；
- 自动化语料库、遥测或少量用户观察都不能替代真实可用性研究；
- 将来如只能招募少量用户，只报告观察事实，不从小样本外推成功率。

### 12.2 M4 强制本地语料库

| 编号 | 验收要求 |
|---|---|
| ACC-CORPUS-001 | 至少 30 份人工维护的黄金表格，每份包含确切预期结果。 |
| ACC-CORPUS-002 | 至少 200 份确定性生成的有效表格。 |
| ACC-CORPUS-003 | 至少 100 份格式错误、超限、压缩炸弹或边界异常等无效／攻击表格。 |
| ACC-CORPUS-004 | 至少 1,000 组固定可复现随机种子的指标性质测试。 |
| ACC-CORPUS-005 | 100% 有效表格完成“导入 → 生成 → 修改时间范围 → 联动重算 → 发布或导出”，并满足数值预期与既定时延预算。 |
| ACC-CORPUS-006 | 100% 无效表格被明确拒绝，且不崩溃、不挂起、不抽样、不截断、不转云端。 |
| ACC-CORPUS-007 | AI 契约测试使用录制响应和模拟供应商验证结构、引用与失败路径。 |
| ACC-CORPUS-008 | 全部语料只在本地浏览器和 CI 运行，不上传官方实例。 |
| ACC-CORPUS-009 | 官方托管版发布前使用维护方真实密钥执行百炼与 Glosc 供应商冒烟测试。 |

上述门槛取代原“50 名用户中 60% 十分钟完成”的发布门槛，但不等价于可用性验证。参见 [ADR-0052](adr/0052-local-corpus-replaces-large-user-study-gate.md)。

## 13. 外部上线依赖

以下事项依赖真实基础设施、第三方服务或设备，必须在官方托管 MVP 上线前闭合：

1. **阿里云北京基础设施**：完成域名备案；验证 OSS 发布密文 Bucket 的不超过 24 小时生命周期和定时清理双保险；确认 CDN 不长期缓存快照；验证函数计算、API 网关和 Tair TTL／原子撤销／配额行为。
2. **百炼真实连接**：使用北京 Workspace、北京 Key 和北京专属域名验证鉴权、模型目录、JSON Mode、限流、错误分类、取消和超时；维护版本化北京模型目录。
3. **Glosc 真实连接**：使用有效密钥验证 `/models`、具体模型的简体中文、结构化输出、流式协议、错误语义；从目标中国大陆网络验证 DNS、TLS 和时延，不宣传未经证实的境内驻留或稳定性。
4. **供应商条款核验**：在上线时点核对两家供应商的当前服务条款、隐私政策、请求／响应留存、训练用途、分包商／上游模型、数据地域、删除机制和 SLA；配置页提供实际链接并标记未核实项，首次真实证据包调用前确认，链接或条款版本变化后重新确认，产品只展示可由有效条款支持的声明。
5. **真实浏览器与设备**：M0 先在当前 iOS Safari、Android 微信和 iOS 微信代表设备完成 KDF/AES/JCS/Fragment 最小探针以冻结 profile；M4 再在所声明版本的 macOS／iOS Safari 和 Android／iOS 微信上执行完整公开检查清单并保存结果，验证加密、交互、二维降级和静态展示。前者不得冒充完整认证。
6. **发布供应链**：公开仓库、AGPL-3.0、社区自托管参考配置、GitHub Actions、校验和与 SBOM 就绪；正式产物只由受保护流水线生成。
7. **安全与留存验证**：完成四 Origin 隔离、分析 Worker 禁网、自定义连接器消息边界、逐路由 CORS、版本化加密信封、密钥／正文日志扫描、严格 CSP、恶意 Schema 夹具、OSS／Tair／日志／遥测删除周期验证和匿名配额测试。

这些外部认证脚本与清单必须开源，但真实密钥、合同信息和真实设备结果不是 Fork 构建开源版本的必要条件。
